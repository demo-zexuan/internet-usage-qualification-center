## 四、验证过程中发现并修复的真实缺陷

以下缺陷均由测试实际暴露，而非事后补充说明：

| # | 缺陷 | 发现方式 | 修复 |
|---|---|---|---|
| 1 | `useAsyncAction` 返回的 `run` 只返回布尔值，调用方在 `await` 后读取的 `data` 来自上一次渲染的闭包，**首次调用必然为 `null`**，导致「开始考试」按钮点击后不跳转 | E2E `full-flow` | `run` 改为直接返回本次调用的 `Result`，全部调用点同步改造 |
| 2 | 证件签发存在**并发竞态**：幂等检查与写入之间的时间窗口内，两次并发调用会各签发一张证件（实测同一场考试产生 2 张证件） | E2E `full-flow`（证书列表出现 4 行而非 2 行） | 签发流程加串行队列 `withIssuanceLock`，并把幂等检查移入临界区 |
| 3 | 成绩页的证件签发副作用使用 `cancelled` 清理标志，依赖变化触发的重跑会**丢弃已成功的签发结果**，导致证件已入库但界面不显示 | E2E `full-flow`（证书已创建但页面无「电子证件已签发」） | 改为组件级 `mountedRef` + 按考试记录 ID 去重的 ref 守卫 |
| 4 | 选项随机化后仍显示题库原始编号，出现「第 4 个选项标着 A」的错乱观感 | 人工审阅截图 | 随机化后按显示顺序重新编号为 A/B/C/D，并重映射正确答案与情景题分值表；题库原始 ID 保留在 `sourceId` |
| 5 | `vite preview` 默认绑定 IPv6 `localhost`，Playwright 的 `127.0.0.1` 探测超时，E2E 无法启动 | E2E 首次运行 | `preview` 脚本固定 `--host 127.0.0.1` |
| 6 | 测试脚手架用 `import.meta.url` 解析数据目录，在 Vitest 的 jsdom 环境下 `import.meta.url` 是 http URL，`fileURLToPath` 直接抛错 | 题库作者反馈 | 改用 `path.resolve(process.cwd(), 'src/data')` |

## 六、未完成事项

以下事项**未实现**，在 [已知限制](已知限制.md) 中有完整说明：

1. **个人数据反向导入** —— 可以导出个人数据 JSON 用于离线查阅，但不能用它恢复考试记录与证件。
2. **真实移动设备验证** —— 响应式布局通过 Playwright 的 Pixel 7 视口验证，未在 iOS / Android 实机上走查。
3. **跨浏览器 E2E** —— 仅覆盖 Chromium，未运行 Firefox / WebKit 项目。
4. **屏幕阅读器走查** —— 已实现 ARIA 语义与键盘操作，但未在 VoiceOver / NVDA / TalkBack 上做完整验证。
5. **WCAG 2.1 AA 逐条审计** —— 未做正式的对照审计，也未提供高对比度主题。
6. **题库可视化编辑器** —— 只支持 JSON 导入导出，管理页面不提供题目编辑表单。
7. **考试记录分页** —— 记录一次性载入，数量极大时可能变慢。
8. **证件批量导出** —— 一次只能导出一张。
9. **覆盖率未达 100%** —— 未设定覆盖率门槛；UI 基础组件（`src/components/ui/`）被排除在覆盖率统计之外。
10. **模拟讨论区持久化** —— 内容仅存在于页面会话中，刷新即重置（这是有意设计，避免演示数据污染真实考试记录）。
